UE5.7 毕设原型 · Ocean Survival

洋流

一个以南海海难为背景的单人生存休闲原型。第一阶段聚焦“小船海面生存 + 资源拾取 + 平台扩展”，先建立可玩闭环，再扩展钓鱼、完整潜水、上岛和邮轮开场。

第一阶段 MVP

目标不是完整开放世界，而是让玩家能在小船平台上移动、维持三条状态、拾取漂浮资源、消耗资源扩展平台。当前版本已经落成到 L_WaterOcean：starter 平台、16 个漂浮资源节点、MVP 输入资产、角色/控制器/GameMode 蓝图、1x1 Deck 数据资产、Space 跳跃、E 水边入口、X 潜水/浮上摄像机往返和 Paper2D 实验状态机/视觉深度偏移均可脚本验证。

出生

玩家带初始物资出现在海面小船平台。

移动

左键点地 + 已修正方向的 WASD 精细移动并存。

拾取

靠近漂浮资源，按 F 加入背包。

生存

体力、水分、饱食度形成持续压力。

建造

资源消耗换取平台扩展和设施占位。

HUD 与背包抽屉

这一轮完成的是 UI/WBP/交互基础设施：低遮挡 HUD 保留海面与平台视野，右侧背包抽屉用 Tab / I 打开，关闭后恢复游戏输入；它还不是最终美术、完整动画抽屉、钓鱼/潜水/上岛事件 UI，也不是最终物品图标替换。

Low Obstruction

HUD 不抢画面

WBP_StatusPanel、WBP_TimePanel、WBP_TopRightPanel 作为轻量信息区，主画面仍留给水面、平台和资源。

Drawer

右侧背包基础

WBP_BackpackDrawer、WBP_InventorySlot 和 WBP_ItemDragVisual 对应槽模型、拖拽合并和后续图标替换。

Command Boundary

UI 只分发命令

物品使用、堆叠合并、生存回复和建造规则仍由 gameplay components 拥有；拖拽放置先查询 placement result，而不是 Widget 直接 spawn actor。

范围边界 / 技术取舍

保留

双移动方式

左键点地移动不删除，保留休闲玩家熟悉的 TopDown 操作；WASD 作为平台微操，已通过 Axis2D modifier 验证 W/A/S/D 输出不同方向。WASD 按下时打断当前寻路目标，避免两套移动互相拉扯。

统一交互

F 负责全部交互

左键只负责移动，F 负责拾取、储物、建造和后续事件，避免“点地移动”和“点资源拾取”冲突。交互失败必须给出材料不足、背包满、距离不够等反馈。

简化

三条状态先行

第一阶段只做体力、水分、饱食度。疾病、温度、睡眠、复杂死亡结算暂不做，降低系统耦合，让生存压力先可见、可调、可测试。

建造边界

模块是格子组

地板可以是 1x1，但建造系统不能退化成单格摆件。储物箱、集水器等模块可以占多个格子，统一使用占格、邻接、旋转和资源消耗规则。

水体边界

逻辑稳定，视觉浮动

水面、浮力和视觉波动服务表现；建造格子保持稳定，不随浪漂移。水上模块和资源 Actor 必须保留浮力组件路径，模型缺失时用立方体占位。

暂不做

钓鱼 / 完整潜水后移

当前已做 X 键最小潜水：角色下到海底/备用深度、摄像机跟随下沉，再按 X 回到水面并还原摄像机；Paper2D 表现层同步切到潜水 Z=300。氧气、海底采集、潜水奖励和完整事件 UI 仍后移。

下一步最小循环

Gameplay

从状态压力到通关

下一轮优先补齐食物/淡水回复、背包 UI、合成配方、事件推进、漂流进度和 7 天到岸终点，让“小船生存”形成完整可通关闭环。

Workflow

GPT 先冻结，DS 再编码

GPT 负责读需求、确认边界、写 Spec 和 TDD 策略；用户确认后再由 DS 进入测试先行编码，继续走保存、关闭编辑器、冷编译、重开项目的自动化链路。

Input Fixed

WASD 向量已闭环

问题定位在 IMC_OceanMVP 映射层：W/A/S 缺少 Axis2D modifier。当前验证 W/A/S/D 分别输出上/左/下/右，点击移动仍保留。

HD2D

Paper2D 只换表现层

角色走 Paper2D / HD2D 表现层，但仍以 BP_OceanSurvivorCharacter 作为 Gameplay Pawn；已导入 192 帧、192 Sprites、24 Flipbooks，并接入相机朝向、动画状态和陆地/水面/潜水三档视觉 Z 偏移。

系统拆分

系统第一阶段职责边界
角色输入BP_OceanMVPPlayerController 绑定左键、触摸、WASD、F、B、R、Space、E、Tab、I。不删除模板点地移动；WASD 打断寻路；B 是建造，Tab/I 是背包，E 只做水边入口判定。
生存状态体力、水分、饱食度随时间变化并显示 HUD。不做疾病、温度、睡眠等复杂生存属性。
背包FOceanItemStack 槽模型支持恢复类物品、拖拽、合并和交换。不做装备栏、耐久、复杂合成树和最终图标美术。
交互靠近可交互 Actor 后按 F 执行。左键不触发拾取，避免输入语义冲突。
建造BP_OceanSurvivorCharacter 默认选中 1x1 Deck；建造组件自动寻找场景平台。模块必须是格子组，逻辑网格不随波浪移动。
资源散播PCG 优先，fallback spawn 保证演示稳定，当前地图生成 16 个 starter 资源。资源避开出生点和平台内部，保留浮力路径。

当前技术基础

Water

已启用水体插件，并保留 WaterBodyCollision 配置，支持海面原型和浮力路径。

Landmass

L_WaterOcean 使用地形/水体支持，避免 WaterBodyOcean 中间缺块等边界问题。

PCG

作为资源散播目标方案；第一阶段允许 deterministic fallback 保障演示稳定。

Grid

建造系统已接入角色、背包和地图平台；未指定目标平台时会自动解析场景中的浮动平台，避免 MVP 建造入口不可玩。

HUD / Backpack

已生成 10 个 /Game/OceanPrototype/UI WBP 资产；WBP_OceanHUDRoot 继承 UOceanHUDRootWidget，控制器绑定到 WBP_OceanHUDRoot_C，并通过真实 PIE 日志验证创建。

Placement Query

拖拽建造先读取 FOceanPlacementQueryResult 的失败原因，UI 只显示反馈和分发命令，不直接生成 Actor。

Paper2D Atlas

角色占位动作集采用“每动作 8x4 单独生成 → 脚本合成 8x20 总 atlas”的流程；五张绿幕源图反推为 222 源定位格，最终用 288 安全格导入，避免 256 切图导致头部/脚蹼裁切。

Paper2D State

Paper2D 原生用 Flipbook 播放帧动画，但没有 SkeletalMesh 那种完整 AnimBP；本项目用轻量 C++ 状态组件做方向判断和 Flipbook 切换，角色类只改表现层相对 Z：陆地 -115、水面 5、潜水 300。

Verification

setup_mvp_survival_loop.py 和 verify_mvp_survival_loop.py 校验 13 个输入映射、控制器绑定、AOceanMVPGameMode 父类、16 个资源节点、Deck 数据、角色建造默认模块和 24 个 Paper2D Flipbook 绑定。
